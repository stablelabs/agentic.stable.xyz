# Agent wallet web app

React and Vite app for Alice's wallet. All owner operations and wallet helpers are imported from the declared `@stablechain/agent-wallet-sdk` dependency. The UI owns wallet connection, forms, browser storage, and presentation.

## Development and checks

Use Node.js 22+ and run these commands from the repository root:

```sh
npm ci
npm run build:sdk
npm run dev --workspace agent-wallet-web
npm run build --workspace agent-wallet-web
npx playwright install chromium
npm run test --workspace agent-wallet-web
```

`npm run dev` at the root builds the SDK and starts Vite. During SDK development, run `npm run dev:sdk` in another terminal to rebuild its exports as source changes.

Local wallet use requires `public/wallet-config.json`, generated by the [operator setup](../../docs/wallet.md#1-set-up-alice-and-the-agent). The app verifies the configured account and connects Alice through Chrome MetaMask. Browser tests provide mocked wallet/RPC responses and do not need Alice's local key or a live account.

Development uses port 5174. Browser tests use port 5175 by default; set `WALLET_TEST_PORT` to choose another test port.

## Configuration and deployment

`deployment/wallet-config.json` contains the versioned public production account settings. Every production build overwrites `dist/wallet-config.json` with that validated allowlist, so `npm run preview` displays the production configuration. Repo-level operator scripts write local public settings to `public/wallet-config.json` for Vite development. Neither file contains signing keys or transaction journals.

`npm run build:cloudflare` generates Worker types and builds the SDK and web app without Foundry. Cloudflare's root configuration serves this package's `dist` and uses `deployment/worker.ts` as its entry. The Worker exposes no payment or signer API; its retired `FundingLedger` export preserves existing storage.

Pushes to `main` deploy through [deploy.yml](../../.github/workflows/deploy.yml). See the [deployment guide](../../docs/wallet.md#deploy) for credentials, public settings, and manual deployment. Package publication uses a separate [tagged release workflow](../../docs/releases.md).
